Project Background
We are building an AI-powered personalised learning platform which aims to deliver intelligent,
adaptive learning experiences for adult learners. A core component is the Unified Skill &
Competency Graph: a knowledge graph that maps relationships between skills, job roles,
industry sectors, and learning pathways. This graph powers our recommendation engine,
learner profiling, and adaptive learning path generation.

Assignment: Build a Mini Skill & Competency Graph System
Design and implement a system that ingests SkillsFuture Skills Framework data into a graph
structure, exposes an intelligent query interface, and layers on natural language querying via
LLM integration.

Data Source
A curated SkillsFuture dataset is provided with your assignment package:
• skillsfuture_dataset.json — a structured JSON file containing 8 sectors, 12 skill
tracks, 52 skills, 18 job roles, 30 courses, 116 edges (relationships), 3 sample learner
profiles, and 5 sample natural language queries.
The dataset is derived from publicly available SkillsFuture Skills Framework data, the SDFE
2025 report, and the MySkillsFuture Course Directory. It is pre-structured to let you focus on
graph modelling and query logic rather than data wrangling.
You may extend or supplement the dataset (e.g., add more edges, skills, or learner profiles)
but the provided dataset is sufficient for a complete submission.

Requirements
Part A: Data Modelling & Ingestion (Required)
1. Design a graph schema that captures relationships between:
• Industry Sectors (e.g., ICT, Healthcare, Financial Services)
• Skill Tracks / Clusters (e.g., Data & AI, Cybersecurity)
• Individual Skills (e.g., Machine Learning, Data Analytics)
• Job Roles (e.g., Data Scientist, AI Engineer)
• Courses / Learning Resources
2. Implement data ingestion that loads the provided JSON into a graph database or inmemory graph structure. Acceptable technologies:
• Neo4j (preferred)
• NetworkX (Python)
• Any graph database of your choice
3. Include at least the following relationship types:
• Sector HAS Skill Track
• Skill Track CONTAINS Skill
• Skill REQUIRED_BY Job Role
• Skill PREREQUISITE_OF Skill
• Course TEACHES Skill

Part B: Query Interface (Required)
Build a query interface (CLI tool, Jupyter notebook, or REST API — your choice) that supports
the following two query types:
1. Learning Path: Given a learner’s current skills and a target job role, compute a
recommended learning path (sequence of skills to acquire, respecting prerequisites).
2. Gap Analysis: Given a learner profile (list of acquired skills) and a target role, return
skill gaps ranked by priority. Suggest relevant courses for each gap.
The provided dataset includes 3 sample learner profiles and 5 sample queries you can use for
development and testing.

Part C: LLM Integration (Required)
Add a natural language query layer so users can interact with the graph using plain English.
Implement support for these 3 query templates:
1. "What skills do I need to become a [target role]?"
2. "I know [skill list]. What’s the fastest path to [target role]?"
3. "Which [economy] skills are most transferable to [other economy]?"
Use any LLM (OpenAI, Anthropic Claude, or open-source). We are evaluating your prompt
design, integration architecture, and how you bridge natural language to structured graph
queries.
Tip: A clean approach is to use the LLM for intent parsing (extracting parameters from natural
language), then execute the structured query against your graph, and finally use the LLM to
format the response.

Part D: Visualisation (Bonus — Optional)
Build a simple web-based visualisation of the graph (or a subset). This could be:
• A force-directed graph (using D3.js, vis.js, or similar)
• An interactive explorer where users click nodes to expand relationships
• A dashboard showing skill demand/transferability metrics

SkillsFuture framework (38 sectors, 119+ job roles, 80+ skills).

Evaluation Criteria
Criteria Weight What We’re Looking For
1. Graph Data Modelling - 20% - Schema design, relationship modelling, handling
of real-world data
2. Code Quality - 15% - Clean architecture, modularity, error handling,
testing
3. Query Logic & Algorithms - 20% - Correctness and efficiency of path-finding and
gap analysis queries
4. Interface Design - 15% - Usability of CLI/notebook/API, clear
documentation, sensible output structures
5. LLM Integration - 20% - Prompt design, intent parsing, graph-to-NL
pipeline, response quality
6. Bonus: Visualisation - 10% - Creativity, usability, integration quality (awarded
only if attempted)

Important Notes
• Python is preferred given our stack.
• You may use AI coding assistants (GitHub Copilot, Claude, ChatGPT, etc.) — we use

• If you make assumptions about the data or requirements, document them clearly.
